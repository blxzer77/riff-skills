## Architecture decisions

Record significant decisions as ADRs in `docs/adr/` (use the writing-adrs skill when
available). A decision is significant when it is costly to reverse: adding or
replacing a framework, datastore, or external service; changing module or service
boundaries; changing a public API or data format; choosing a cross-cutting approach
(auth, error handling, state, concurrency). Write the ADR in the same change that
implements the decision, and supersede old ADRs instead of editing their decisions.
